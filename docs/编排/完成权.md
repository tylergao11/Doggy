# 完成权（Round vs Task）

← [返回总览](../编排.md)

> Doggy 对上游 Grok Build 的**根因级**分歧：谁有权说「任务结束」。

---

## 一句话

**Round 结束 ≠ Task 结束。完成权只属于 TaskOrchestrator，不属于模型。**

---

## 两个概念

| 概念 | 含义 | 谁决定 |
|------|------|--------|
| **Round** | 一次「想→做→想」，直到模型本轮不再调 tool（或取消/权限/max_turns） | `process_conversation_turn` |
| **Task** | 用户目标从开始到**验收通过** | **TaskOrchestrator 独占** |

| 规则 | 说明 |
|------|------|
| Round 完 ≠ Task 完 | `TurnOutcome::Completed` 只表示停采样 |
| 模型无 TaskComplete | 不调 tool / `update_goal(completed)` 最多表示「请求验收」 |
| 唯一 TaskDone | `OpenItems` 为空 **且** goal verification（classifier / skeptics）**Achieved** |

---

## 根因（上游为何早停）

1. **语义混用**：模型停采样被当成任务完成  
2. **完成权在模型**：无 tool 或 `completed:true` 可结束任务  
3. **任务编排可选**：Goal/laziness/classifier 是旁路；还有 FailOpen→完成  

源码对照：`handle_prompt` 外环在 `!goal_active` 时直接 `break`；Goal 路径里 `prepare_goal_continuation → None` 即 EndTurn。

---

## 权威完成路径

```text
Round 结束
  → run_doggy_round_end
      → drain update_goal（跑 classifier / skeptics）
      → 用户取消 / budget / round 失败 → TaskPaused（不是 Done）
      → open items 非空 → Inject(Continue) → 再 Round
      → open 空 + verification Achieved → TaskDone（唯一终态）
      → open 空 + verification Rejected → Inject(Fix, gaps) → 再 Round
      → open 空 + verification Pending → Inject(Continue, 请 re-verify) → 再 Round
```

- **不再** spawn 独立的 Doggy audit subagent（已删除；验收只用 goal classifier）  
- 验证不通过：**一直改**，不设「失败 N 次放弃」  
- 安全阀仅：**用户**、**infra**、**总预算** → `Paused`，禁止假 Done  
- **禁止** FailOpen → Done  

---

## Open items

1. 结构化未完成子项（goal/checklist / todos）  
2. 若无子项：隐式项 **「验收未通过」**，直到 verification Achieved  

模型空口「做完了」**不能**清空 open items。

---

## 源码位置

独立纯逻辑 crate（零 host 依赖，Windows 也可单测）：

```text
crates/codegen/xai-doggy-orchestrator/src/
  lib.rs           // 模块入口
  state.rs         // TaskPhase / TaskStatus / PauseReason
  open_items.rs    // OpenItemsSnapshot
  audit.rs         // Finding 类型（Fix 注入复用）
  inject.rs        // Continue / Fix 注入载荷
  decide.rs        // decide_after_round 纯决策 + 单测
```

Shell 重导出：`xai_grok_shell::session::orchestrator`

### Host 接线

| 点 | 行为 |
|----|------|
| `handle_prompt` 外环 | Active goal 走 `run_doggy_round_end` |
| 自由聊天 | 无 Active goal → 单轮结束（非任务） |
| `update_goal(completed:true)` | 只写 classifier verdict，**不再** `tracker.complete()` |
| FailOpenAchieved | 记为 NotAchieved，**禁止**假完成 |
| 验收 | **goal classifier / skeptics**（无独立 doggy-audit subagent） |
| 唯一 Complete | `doggy_mark_task_done`（orchestrator TaskDone 之后） |
| budget | doggy 轮末 + turn 成功/失败路径均 `enforce_goal_token_budget` → Paused，非 Done |
| cancel / 连续失败 | 失败 streak → BackOff pause；**不是** TaskDone |

### TUI 展示

| 位置 | 内容 |
|------|------|
| Status chip | Doggy `completion_phase`：`checking` / `executing` / `fixing` / `done` / `paused` |
| Goal detail modal | Completion gate phase + findings |

### 已知死锁 / 冻住（已修）

#### 1) 不可重入锁

`doggy_mark_task_done` 曾在**已持有** `goal_tracker`（`parking_lot::Mutex`，**不可重入**）时调用 `prune_subagent_records_for_active_goal()`，后者再次 `goal_tracker.lock()` → 同线程死锁。

#### 2) LocalSet 上同步 FS

即便锁序正确，在持锁（或 LocalSet 线程上 `await` 阻塞池）时做 `rescue_classifier_details` / `remove_dir_all`，Windows 杀毒/文件锁会把 **整条 session actor** 卡住：

- `completion_phase` 永久停在 `checking`（Achieved 之后、`complete()` / UI `done` 之前）
- LocalSet 冻住 → `shell.cancel.received` 有日志但 **`cancel.processing` 永远不出现**
- 新消息 `prompt.drain_blocked reason=turn_running`

#### 修复（必须同时满足）

1. 先 prune（自带短锁），再单独加锁做 **纯内存** `complete_defer_scratch_cleanup()`  
2. 立刻 `doggy_emit_completion_ui("done")`（chip 不再卡 checking）  
3. rescue + `remove_dir_all` 放锁后 **`spawn_blocking` fire-and-forget**（禁止 await）  
4. **禁止**在持有 `goal_tracker` 时再调会加同锁的 helper  

#### 部署坑（真实复发根因 2026-07-31）

源码修了但用户 PATH 上的 `~\.Doggy\bin\doggy.exe` 仍是旧包：

1. 正在跑的 `doggy.exe` **锁文件** → 安装只能写成 `doggy-next.exe`  
2. `where doggy` **永远解析 doggy.exe**，不解析 `doggy-next`  
3. 结果：Agent 说“已安装新版”，用户新开窗口仍是旧包  

**正确安装（`scripts/build.ps1` 已改）**：锁住时 **rename** `doggy.exe` → `doggy-prev.exe`，再拷新 `doggy.exe`（Windows 允许 rename 正在运行的映像）。禁止只写 `doggy-next` 就宣称修好。

验收（必须对 **where 解析出的第一个路径**）：

```powershell
powershell -File $env:USERPROFILE\.Doggy\bin\verify-doggy-fix.ps1
# 或
$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")
$p = (where.exe doggy | select -first 1); findstr doggy.mark_done.state_done $p
```

- 必须打印 `OK` / 找到 `state_done`  
- **当前** Agent 窗口内存里仍是旧映像；**关掉后新开**才加载磁盘上的新 `doggy.exe`  
- 日志：`doggy.after_round` / `doggy.mark_done.enter` / `doggy.mark_done.state_done` / `doggy.mark_done.exit`；取消应有 `shell.cancel.processing`

Wire：`GoalUpdated.completion_phase` + `completion_findings[]`（shell → pager）。

源码：
- 策略：`xai-doggy-orchestrator`
- Host：`session/acp_session_impl/doggy_gate.rs` · `turn.rs`
- TUI：`pager` `agent_status` / `goal_detail` / `GoalDisplayState.completion_*`

## 代码不变量

1. 全局仅 Orchestrator 可产生 `TaskDone`  
2. `TurnOutcome::Completed` 禁止直接映射为任务结束  
3. 不存在 FailOpen → Done  
4. Continue 与 Fix 单一 inject 语义  
5. **不存在** Doggy audit subagent 完成路径
